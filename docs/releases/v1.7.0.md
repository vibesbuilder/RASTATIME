## RASTATIME v1.7.0 (2026-11-16)

A feature release on top of 1.6.0. Shows get a **show type**, and the reports count repeats by
it. A show DJ may **connect five minutes before the show**. Two playout fixes make hand-overs to
live inputs cleaner. It contains **one database migration** (0088) and a **new PHP class**; see
*Upgrading* before you install.

### Added

- **Show type per show** (*Settings → Show Types*, a new menu item below Track Types).
  - A list of show types with code, label, order and the box **Counts as repeat**. Each row
    shows how many shows use the type.
  - A new installation brings Music, Live, Recording, Repeat (counts as repeat), News and
    Partner show. Rename, add or delete them as you need; a deleted type leaves its shows
    without a type.
  - *Edit Show → What* has a **Show Type** select next to Genre. Show templates and the show
    import / export (column `show_type`, label or code) carry it.
  - `manage.py transfer_genre_to_show_type` moves show types that a station kept in the genre
    field so far: `--map GENRE=TYPE`, `--dry-run`, a JSON `--backup` and `--clear-genre`.
- **A show DJ may connect up to five minutes before the show** (fixed).
  - The login of a host of the **next** show is accepted. The broadcasting software shows
    "connected" and can be checked, but the DJ stays off air until the show starts; the show
    on air continues.
  - At the start the DJ is on air to the second, without the pre-buffer gap.
  - While a DJ waits, the header shows *waiting until 10:07* in place of *Show Source*.
  - Liquidsoap sets the gate only once the connection really stands: the harbor checks the
    login before it checks whether the mount is taken, so a refused early login can never take
    the DJ on air off the air. Liquidsoap opens the gate at the start time on its own.

### Changed

- **Repeats are counted by the show type.** A show whose type is marked *Counts as repeat*:
  - counts in the repeats column of *Analytics → Programme Minutes*;
  - counts no people in *Analytics → People Involved*;
  - is not archived to cba.media automatically (web application and archive worker).
  - "Repeat of another show" only copies content now.
- **Programme Minutes** groups by **Show type** (the default) next to genre and category. The
  show list and both CSV exports have a show type column.

### Fixed

- **"Back on air soon" flashed at every hand-over to a live input.**
  - The off-air text went out as soon as the queue fell into silence for a few milliseconds:
    between a news intro and the web stream, and at every line-in start. It reached the stream
    title, the Live Text and public title lists.
  - It now appears only after **5 seconds** of real silence, and only if no live input took
    over.
- **A line-in show started 1-2 seconds late.**
  - The pre-warm 15 s before the slot did not connect the Liquidsoap input: the fresh input per
    slot only starts when something pulls it, and with the gate closed nothing did.
  - A silent output now pulls the prepared input, without a buffer and without added latency;
    the line-in is on air the moment its gate opens.
- The German translation of the *Track Types* menu item ("Track-Typen").

### Upgrading from 1.6.0

Follow `docs/operator/UPGRADE.md`. In short:

1. Make a backup (*Settings → Backup*).
2. Stop RASTATIME-ANALYZER (it locks its executable), update the checkout and reinstall the
   five backend packages (`pip install -e`) so the services report 1.7.0.
3. **Run `composer dump-autoload`** in `frontend\legacy`. The show types bring a new PHP class
   (`Application_Model_Showtype`); without it the show form and *Settings → Show Types* fail.
4. **Run the migration** (`manage.py migrate legacy`): 0088 show types. The code tolerates the
   missing migration: until it runs there are no show types, no field in the show form,
   Programme Minutes counts no repeats, and archiving keeps the old "Repeat of" rule.
5. **Give your repeat shows a show type.** After 0088 no show has a type yet, so a show set up
   as "Repeat of another show" no longer counts as a repeat - in Programme Minutes, People
   Involved and the **automatic CBA archiving**. Set the type *Repeat* on them (Edit Show →
   What) before the next automatic archive run. If your genre field holds show types, use
   `manage.py transfer_genre_to_show_type --dry-run` first.
6. **Apache**: restart it, which loads the new translations.
7. Start the services in order (`docs/operator/RESTART_ORDER.md`): API before PLAYOUT.
   PLAYOUT writes a new Liquidsoap script (off-air delay, line-in warm-up, early DJ login) and
   **restarts Liquidsoap at once** because the script changed - about 10-15 s off air, so pick
   a quiet moment. Restart RASTATIME-WORKER so the archive worker reads the new repeat rule.

### Known limitations

- Windows only.
- `RASTATIME-WORKER` runs from the source tree. It has no wheel among the release files.
- The tempo / key worker (`backend/features`) runs from the source tree in its own environment.
  It has no wheel either.
- The Show Source mount takes one client at a time: while the DJ of the show on air is
  connected, nobody can connect early.

The full change history is in `CHANGELOG.md` (German).
