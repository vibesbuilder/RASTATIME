## RASTATIME v1.8.0 (2026-11-22)

A feature release on top of 1.7.1:

- Live DJ inputs get an **automatic level**.
- The calendar exports its view as **PDF**.
- The import refuses **damaged or cut-short files**, and a library scan finds those already
  imported.
- The schedule can **keep running under a DJ** (stage 1, behind a trial switch).
- Several fixes for live hand-overs and scheduling.

It has **no database migration** and **no new PHP class**. PLAYOUT restarts Liquidsoap once;
see *Upgrading* before you install.

### Added

- **Automatic level of the live DJ inputs** (*Settings → Streams → DJ Hand-over*, box **Level
  live DJ inputs**, on by default).
  - Master Source and Show Source had no level stage. A hot DJ encoder reached the stream about
    7 dB louder than the programme, with peaks above 0 dBFS.
  - A slow automatic gain control (Liquidsoap `normalize` in LUFS mode, in front of the source
    switch) brings both DJ inputs to the -23 LUFS of the library. Loud passages come down within
    about two seconds and quiet ones go up over about ten. The correction range is -24 to
    +12 dB.
  - Silence and a muted microphone are not raised.
  - It can be switched off live with `var.set dj_level.enabled = false` on the Liquidsoap
    telnet port.
- **Calendar view as PDF.** An export button left of *Day / Week / Month* opens a dialog with
  two layouts:
  - **List** (every view): one page per day, with time from - to and the show in its colour.
    It covers a day, the week around a date (the week start comes from *Settings → General*) or
    any period of up to 92 days.
  - **Calendar** (day and week): the time grid of the calendar and the Multi-View widget. The
    week puts seven days on one page; the day is split into columns, so that short shows also
    get a line of text.
  - Both layouts come in landscape or portrait. The PDF is made in the browser with pdfmake,
    which is loaded on the first export only.
- **The import refuses damaged or cut-short files.**
  - The analyzer's playability check now compares the decoded length with the declared length.
  - The import fails when more than 2 s and more than 1 % are missing. The reason shows in the
    failed list of the upload page, for example *it decodes only 87.9 of its 293.4 s (damaged
    or cut short)*. The original stays in `organize/`.
  - Such files used to play into dead air long before their cue-out.
- **Library scan for damaged files**: `rastatime-api scan_damaged_files`.
  - It decodes every library file once, with the same rule as the import check, and writes a
    CSV report to `logs/damaged-files-<date>.csv`. Cut-short, undecodable, missing and too-slow
    files are listed.
  - It changes nothing; you decide per file.
  - About 50 minutes for 25,000 files on one core at low priority. `--resume` continues after
    an interruption.
- **The schedule keeps running under a DJ** (stage 1, trial switch `RASTATIME_SCHEDULE_UNDER_DJ=1`
  in the environment of RASTATIME-PLAYOUT, off by default).
  - A silent second consumer pulls the schedule chain for exactly as long as a DJ holds the bus.
    File rows start, queue and stop as without a DJ, only unheard.
  - When the DJ ends, the programme is already at the right place.
  - Without the switch, the Liquidsoap script and the behaviour are unchanged.

### Changed

- **Duplicate Playlist / Duplicate Smart Block** have their own icon in the library context menu
  (two sheets with a plus) instead of the pen of *Edit…*.
- **`bulk_import --allowed-extensions` replaces the default list** instead of adding to it, so
  `--allowed-extensions mp3,flac` now limits an import to MP3 and FLAC. The option is
  repeatable or takes a comma list. The default list now also holds .mp4, .mp2, .mp1 and .au,
  like the upload page and the import folder.

### Fixed

- **The Show Source ends with the show.**
  - A show DJ stayed on air up to 6 s past the end of the show, and the next show lost its
    opening.
  - The login check now names the end of the show. Liquidsoap closes the show source to the
    second, and PLAYOUT hands over to the schedule without a resume.
  - The next show starts on time with its first element, and the DJ fades out below it. A show
    end moved in the calendar is followed.
- **At a Show Source end, the track that was paused when the DJ took over came back** instead
  of the next show's first element.
  - PLAYOUT now replaces the paused queue half a second before the show end. The first file of
    the next show starts in the frame in which the show source closes.
  - A resume after a DJ who disconnects also cuts the paused rest.
- **A web stream or line-in row that ends under a DJ releases its source.** Before, the source
  stayed open until the next start, and a DJ leaving into a gap could have brought the ended
  input back on air.
- **The firewall watcher no longer blocks again after an Unblock or a successful DJ login.**
  - Every Unblock (*System Status* or `rt-blocks.ps1 -Unblock`) records its time in
    `config/unblocked.txt`. The watcher ignores that address's older log lines.
  - Wrong DJ passwords count only after the address's last successful DJ login.
  - Before, a DJ with an encoder that once retried a wrong password was blocked again after
    every unblock and disconnected a few minutes later.
- **Automated fillers fill only one episode of a linked show.** The Auto DJ fill pass,
  autoloading and *Repeat of show* went through the linked-show path and wrote into every future
  episode. The task manager also runs one cycle at a time now (PostgreSQL advisory lock).
- **The date picker popup was narrower than its month table** (all date fields). The header now
  is as wide as the calendar.
- **The analyzer is ready for ffmpeg 9.1.**
  - ffprobe 9.1 writes the comment of an ID3 frame as `comment-<language>`. Without the fix,
    the comment in the ID3 chunk of a WAV file was lost; both spellings are read now.
  - The length and bit rate of raw ADTS AAC files are measured from their packets instead of
    being estimated from the first frames. The estimate turned 6 s with a quiet start into
    90 s, which the new import check would have refused.
  - The analyzer tests pass on ffmpeg 9.0 and 9.1; CI tests both.

### Upgrading from 1.7.1

Follow `docs/operator/UPGRADE.md`. In short:

1. Make a backup (*Settings → Backup*).
2. Stop RASTATIME-ANALYZER (it locks its executable), update the checkout and reinstall the
   five backend packages (`pip install -e`) so the services report 1.8.0.
3. There is **no migration** and no `composer dump-autoload` is needed.
4. **Apache**: restart it, which loads the new translations (export dialog, DJ level setting).
5. Start the services in order (`docs/operator/RESTART_ORDER.md`): API before PLAYOUT.
   - PLAYOUT writes a new Liquidsoap script (DJ level, show source end) and **restarts
     Liquidsoap at once**, because the script changed. That is about 10-15 s off air, so pick a
     quiet moment.
   - RASTATIME-ANALYZER brings the import check for damaged files and the ffmpeg 9.1 support.
6. The firewall watcher task runs `infra\scripts\rt-firewall-watch.ps1` from the checkout and
   picks up the new version at its next run.
7. Optional:
   - Run `rastatime-api scan_damaged_files` once and look through the report.
   - To try the schedule under a DJ, set `RASTATIME_SCHEDULE_UNDER_DJ=1` in the environment of
     RASTATIME-PLAYOUT and restart it. Liquidsoap restarts once.

### Known limitations

- Windows only.
- `RASTATIME-WORKER` runs from the source tree. It has no wheel among the release files.
- The tempo / key worker (`backend/features`) runs from the source tree in its own environment.
  It has no wheel either.
- The Show Source mount takes one client at a time: while the DJ of the show on air is
  connected, nobody can connect early.
- The schedule under a DJ covers file rows. A web stream or line-in row that falls under a DJ
  still starts when the DJ ends.
