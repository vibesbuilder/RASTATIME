## RASTATIME v1.2.0 (2026-11-05)

A release on top of 1.1.0: a buffer per webstream, safer recovery after
an unplanned engine restart, a public read API that gives away less and
a now-playing endpoint that works.  Nothing of 1.1.0 is removed.

### New

- **Buffer per webstream.**  The webstream dialog has **Buffer (s)** and
  **Buffer max (s)** (empty = the defaults of 5 s and 10 s).  *Buffer max*
  is the delay added on top of the server's own connect burst and at the
  same time the reserve against dropouts: smaller values bring the
  stream closer to live, larger ones give more reserve.  The values
  apply from the next start of the stream and travel with the webstream
  export and import (`webstreams.csv`).
- **Manual chapter API** in all four languages: who may read what, the
  *Public RASTATIME API* switch the widgets depend on, the public read
  endpoints with their parameters, API v2 with Swagger after login,
  examples, and why the single API key never leaves the station.

### Changed

- The README describes RASTATIME as it is today: features, requirements
  as in production, a short getting started that points to the
  installation guide, the eight services and a map of the documentation.

### Fixed

- **Recovery after an unplanned Liquidsoap restart.**  A restart could
  make a file play twice: the playout noticed the restart late and
  pushed a catch-up copy behind the one the fresh engine was already
  playing.  Now every telnet reconnect checks for a restart within a
  second, the playout adopts the request the engine is playing instead
  of pushing a second copy, and a clock check cuts to the schedule when
  the engine's remaining time fits neither the current nor the next
  item.
- `/api/v2/now-playing` always answered "nothing is playing".  It now
  reads the schedule like the widgets do: the current file, webstream or
  line-in with its credits, the current show, the next item and the
  source (scheduled, live DJ or master DJ).

### Security

- The public live-info endpoints (`/api/live-info`, `/api/live-info-v2`)
  returned the whole library row of the playing track, including its
  file path and internal fields.  They now return only the credit fields;
  `/api/shows` no longer lists internal playlist IDs.  The OpenAPI schema
  and the Swagger UI under `/api/v2/schema` require a login.  The embed
  widgets are unchanged.

### Upgrading from 1.1.0

Follow `docs/operator/UPGRADE.md`.  In short:

1. Make a backup (*Settings → Backup*).
2. Stop the RASTATIME services; the running analyzer locks its
   executable, and a reinstall with the services running fails halfway.
3. Update the checkout and reinstall the five backend packages
   (`pip install -e`) so the services report 1.2.0.
4. Apply the **database migration** 0079 (`manage.py migrate`; two
   optional columns on the webstream table).
5. Start the services in order (`docs/operator/RESTART_ORDER.md`).
   PLAYOUT renders a new Liquidsoap script, so `RASTATIME-LIQUIDSOAP`
   restarts as well; Apache loads the new translations.

### Known limitations

- Windows only.
- `RASTATIME-WORKER` runs from the source tree; it has no wheel among
  the release files.

The full change history is in `CHANGELOG.md` (German).
