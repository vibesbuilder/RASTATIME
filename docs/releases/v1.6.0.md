## RASTATIME v1.6.0 (2026-11-15)

A feature release on top of 1.5.0. The library learns **energy, brightness, tempo and key** of
the music, recordings can be copied to the show makers' network folder, and the Auto DJ closes
small leftover gaps with a buffer track. It contains **five database migrations** (0083-0087)
and two new Windows tasks; see *Upgrading* before you install.

### Added

- **Energy and brightness per track** (*Library*).
  - Every music track gets two values from 1 to 10, compared with the station's own library:
    **Energy** (calm ... very energetic) and **Brightness** (dark ... bright).
  - Measured by ffmpeg on 30 seconds from the middle of the track, brought to the on-air level
    first, so the mastering loudness does not decide on its own.
  - The levels are the deciles of the whole library: each level holds about a tenth of the
    music.
  - The Windows task *RASTATIME-AudioFeatures* measures new tracks every ten minutes, below
    normal priority. Import and playout do not wait for it.
  - Library columns *Energy* / *Brightness* (hidden by default, sortable, range search), fields
    in Edit Track and smart block criteria *Energy* / *Brightness*.
- **Tempo and key per track.**
  - The same task measures the **tempo** (into the existing BPM field) and the **musical key**,
    shown as Camelot code and chord name, for example **8A · Am**.
  - It uses librosa in its own Python environment (`.venv-features`, about 420 MB), so the
    production environment stays without numpy / numba.
  - The tempo counts the strongest pulse, as most DJ software does. Reggae, for example, mostly
    comes out at double time.
  - Library column *Key* (hidden by default; its search finds `8A` or `Am` exactly), a key
    select in Edit Track and the smart block criterion *Key* (*is* / *is not*, a list of the 24
    keys).
  - Without the environment, tempo and key are simply skipped.
- **A value entered by hand always wins** for energy, brightness, BPM and key. So does a BPM tag
  of the file. A new measurement or a new scale never replaces it, and the help icons show the
  measured value.
- **Audio features per track type** (*Settings → Track Types → Analyze audio features*).
  - Only tracks of a type with this checkbox are measured. The migration ticks it for *Music*
    only, and tracks without a track type are never measured.
  - Unticking a type keeps the values measured before, so smart blocks keep their picks.
    `manage.py analyze_audio_features --clear-unselected` removes them; hand values stay.
- **Loudness analysis per track type** (*Settings → Track Types*).
  - *Analyze loudness* can be switched off for a type, with a *Fixed Gain (dB)* (-30 to 30)
    instead of the measured adjustment.
  - Meant for spots over the same sound bed, which a per-file measurement levels differently
    from spot to spot.
- **Copy finished recordings to a second folder** (*Settings → Local Machine → Show
  Recording*).
  - Every finished show recording is copied once to a folder, for example a network share of
    the show makers.
  - The copy keeps the file name, is written as `.part` first, and never deletes or overwrites
    anything at the target.
  - The Windows task *RASTATIME-RecordingCopy* runs under an account that may write there.
- **Record Start offset** (*Settings → Local Machine → Show Recording*, -60 to 60 s). It moves
  the start and the end of every show recording, for example to match the delay of a line
  input. The length stays the same.
- **Auto DJ buffer track** (*Settings → Auto DJ → Buffer Track*).
  - When nothing in the Auto DJ playlist fits a leftover gap of 5 s up to *Maximum Gap*, a long
    track from the buffer playlist fills it. It is cut or faded out at the show end.
  - It is the only item allowed to run past the show end. Show-Shift, the Show Builder and
    repeats take it into account.
- **Day teasers "soon" and "now"** next to show / today / tomorrow. The limits are under
  *Settings → General → Automation*.
- **My Podcast: published until.** The publish dialog takes the last day a track stays in the
  station podcast. A nightly task withdraws it like *Unpublish*.
- **Song requests.**
  - New page *Widgets → Song Request* with status, live preview and embed code.
  - The listener widget has a search box over the whole pool. Before, the list stopped at the
    letter A, about 90 % of the pool out of reach.
  - All twelve listener texts can be replaced under *Listener texts*.
- **Widgets size themselves.** Every `/embed/` widget reports its content height. The new
  `/embed/widgets.js` on the station website sets the iframe height (one script line per
  page; without it the fixed `height` stays).
- **Help icons** for the intro / outro autoloading playlist (*Settings → General →
  Automation*).

### Changed

- **Settings menu order**: My Profile, General, Users, Streams, Local Machine, Track Types,
  Auto DJ, Show Templates, Archiving, Alerts, Import / Export, Backup, Status.
- **Re-read Tags** keeps the measured tempo when the file has no BPM tag.

### Fixed

- **A removed line-in or web stream** released only the recording, not its Liquidsoap input.
  - The input kept polling a vanished mount, and Liquidsoap grew by about 140 MB per hour.
  - Both are now stopped like at a regular slot end.
- **An overbooked row ended early by its cue-in.** The API now adds the cue-in when it caps the
  cue-out at the show end.
- **Edit Track: Save** closes the tab again and redraws the library.
- **My Podcast**:
  - *Save* no longer ends in error 500, and privacy and feed address are stored.
  - The episode list shows its episodes again.
  - *Unpublish* on an episode that is already gone no longer fails.
- **Song request widget**:
  - The answer to a request appears under the clicked title.
  - Long titles no longer cut off the button.
  - The listener texts are translated.
- **Widgets**:
  - Track History honours `?min_sec=`.
  - The public `show-history-feed` lists shows again.
  - The `/embed/` frame rule matches case-insensitively.
- **Manual**:
  - Traffic Alerts now explains the ten-minute deadline correctly: a slot is fixed up to five
    minutes before it airs, so slots belong about five minutes apart.
  - WIDGETS and API are corrected.

### Security

- **Legacy read endpoints honour the public-API switch.** `shows`, `show-schedules`,
  `show-tracks`, `item-history-feed` and `show-history-feed` answered even with the switch off.
  `show-tracks` no longer shows a web stream's source URL or the login of its creator.

### Upgrading from 1.5.0

Follow `docs/operator/UPGRADE.md`. In short:

1. Make a backup (*Settings → Backup*).
2. Stop the RASTATIME services. The running analyzer locks its executable, so a reinstall with
   the services running fails halfway.
3. Update the checkout and reinstall the five backend packages (`pip install -e`) so the
   services report 1.6.0.
4. **Run the migrations** (`manage.py migrate legacy`): 0083 loudness per track type, 0084
   podcast *published until*, 0085 energy / brightness, 0086 musical key, 0087 audio features
   per track type. The code tolerates a missing migration, so the order of code, migrations and
   restarts does not matter.
5. **Register the new Windows tasks** once, in an elevated PowerShell:
   - `infra\scripts\register-audio-features.ps1` for energy / brightness / tempo / key;
   - `infra\scripts\register-recording-copy.ps1 -User <account>`, only if you set a copy
     folder (*Settings → Local Machine*).
6. **For tempo and key**, install their environment once:
   `infra\scripts\install-features-venv.ps1` (downloads librosa and its dependencies from
   PyPI, no service restart). The first pass over a library takes about two hours
   (`manage.py analyze_audio_features --limit 0 --max-seconds 0`); otherwise the task catches
   up by itself.
7. **Apache**: deploy `infra\apache\rastatime-https.conf` (the case-insensitive `/embed/` rule)
   and restart Apache, which also loads the new translations.
8. Start the services in order (`docs/operator/RESTART_ORDER.md`): API before PLAYOUT. PLAYOUT
   writes a new Liquidsoap script (buffer track fade), which takes effect at the next Liquidsoap
   restart.
9. No `composer dump-autoload` needed.

### Known limitations

- Windows only.
- `RASTATIME-WORKER` runs from the source tree. It has no wheel among the release files.
- The tempo / key worker (`backend/features`) runs from the source tree in its own environment.
  It has no wheel either.

The full change history is in `CHANGELOG.md` (German).
