## RASTATIME v1.11.0 (2026-11-24)

A feature release on top of 1.10.0, made for the people behind the shows:

- **host names per show**, so that People Involved counts each person once;
- **Programme Minutes per host name**;
- **the link of a new cba.media post by e-mail to the producers**;
- **colours per show type**.

It brings **two database migrations** (0089, 0090) and **no change to the playout script**:
Liquidsoap does not restart. See *Upgrading* before you install.

### Added

- **Host names per show** (Edit Show → What, below *Own production*).
  - *Hosts involved* used to be a number per show, so a person who hosts two own productions
    counted twice in Analytics → People Involved.
  - Shows now get the names of their hosts as chips, with suggestions from one register of
    persons (migration 0089: `cc_person`, `cc_show_person`; one name = one person, case does
    not matter, `;` separates names, also when pasted).
  - With names, *Hosts involved* is their number (read-only). Without names, the number
    works as before.
  - People Involved counts every named person once per year, however many shows they host:
    - a *Host names* column;
    - a *Shows without host names* card;
    - a *Hosts in several shows* list;
    - a CSV with the names.
  - New page **People Involved → Host Names**: rename, merge and delete names.
  - Show templates carry the names and the number (the number was not captured before).
    Import / Export (shows) has the columns `hosts_involved` and `host_names`.
- **Programme Minutes per host name** (Analytics → Programme Minutes → *Group by* → *Host name*).
  - The same minutes per person.
  - A show with several hosts counts fully for each of them, so the rows add up to more than
    the total. The *Total* row counts every show once; page and CSV say so.
  - A show counts only with its own names: a repeat show without names of its own appears
    under *No host names*.
- **The link of a new CBA post by e-mail** (Settings → Archiving → *Link by e-mail*, admins).
  - When an upload to cba.media has finished, the background service e-mails the link of the
    new post (`https://cba.media/?p=<number>`) to every active producer of the show with an
    e-mail address, one e-mail per producer.
  - It goes out after every finished upload, also after *Archive again*. It does not go out
    when a post is linked by hand.
  - **Off by default.** Subject and text are free, with the placeholders `{name} {show} {title}
    {date} {time} {link} {station}`. A post with the visibility *private* gets an extra
    sentence, because its link works only for the CBA account.
  - Sent over the SMTP server and sender of Settings → Alerts. Without them, the section says
    so and nothing is sent.
  - A failed e-mail never changes the upload. Archive Status shows in the *Note* to whom the
    link went or why not, and the CSV has the column *Link e-mail* (migration 0090).
- **Colours per show type** (Settings → Show Types).
  - Each type can have a background and a text colour (migration 0090), set with the colour
    picker of the show form.
  - Choosing a type by hand under New Show / Edit Show fills the show's colours, which can still
    be changed. Opening a show or applying a template never recolours.
  - **Apply colours** in the row of a type gives every show of the type its colours, after a
    question. A colour the type leaves empty stays as each show has it.
- Manual (all four languages): Calendar, Archiving, Analytics, Import / Export, Show Templates,
  Settings.

### Fixed

- Show templates stored the category and the show type but never wrote them back into the form.
  They do now.

### Upgrading from 1.10.0

Follow `docs/operator/UPGRADE.md`. In short:

1. Make a backup (*Settings → Backup*).
2. Update the checkout.
3. Stop **RASTATIME-ANALYZER** first (it locks its executable). Then reinstall the five backend
   packages (`pip install -e`).
4. Apply the **database migrations** 0089 and 0090 (`manage.py migrate`). Both only add tables
   and columns and take under a second. Code and migrations may come in either order: before
   the migrations, the new fields and pages stay hidden.
5. Restart the services in order (`docs/operator/RESTART_ORDER.md`).
   - **RASTATIME-WORKER** must restart for the link e-mail.
   - **RASTATIME-APACHE** must restart for the new translations.
   - The playout script is unchanged, so a PLAYOUT restart does not restart Liquidsoap.
6. No `composer dump-autoload` is needed.
7. Optional:
   - turn on *Link by e-mail* and test it with yourself as producer of a test show (a real
     upload to cba.media);
   - give the show types their colours.

### Known limitations

- Windows only.
- `RASTATIME-WORKER` runs from the source tree. It has no wheel among the release files.
- The tempo / key worker (`backend/features`) runs from the source tree in its own environment.
  It has no wheel either.
- Guests have no names yet; only the hosts of a show do (BACKLOG).
- The link e-mail has no test button. The first test is a real upload.
- The Show Source mount takes one client at a time: while the DJ of the show on air is
  connected, nobody can connect early.
- The schedule under a DJ (trial switch since 1.8.0) covers file rows. A web stream or line-in
  row that falls under a DJ still starts when the DJ ends.
- The playout itself does not yet notice a file Liquidsoap refuses at playout time. A check of
  the next 48 hours in the preflight is planned (BACKLOG).
