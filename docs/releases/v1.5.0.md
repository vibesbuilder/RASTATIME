## RASTATIME v1.5.0 (2026-11-11)

A security and maintenance release on top of 1.4.0. It comes from the first CodeQL code scan
after the repository went public. It fixes the real findings, removes the legacy md5 password
fallback, and replaces four old JavaScript libraries. It contains **no database migrations**.

### Security

- **Podcast episode dialog.**
  - The episode description from an external feed used to be inserted into the page as HTML.
    Only SimplePie's incomplete attribute blacklist stood between a crafted feed and script in
    the operator's browser.
  - It is now parsed in inert documents and shown as plain text. Paragraphs and line breaks are
    kept.
- **Editor tab names.** A track title from the file tags or a playlist name was put into the tab
  label as HTML. It is set as text now.
- **Cue editor.** Cue values are set as text.
- **Directory listing removed.**
  - `/preference/server-browse` (left over from an old media-folder dialog that was never loaded)
    let any Admin list the sub-folders of any path on the server.
  - The action, the never-loaded `serverbrowser.js` / `musicdirs.js`, the unused watched-folders
    form and the `directory-config` stub are gone.
- **Icecast password in the line-in debug log.** The FFmpeg command line written at debug level
  carried the source password. Both log sites now mask it.
- **md5 password fallback removed.**
  - Since 1.0.0 passwords are stored with bcrypt, and an old unsalted md5 value was still accepted
    and re-hashed at the next login.
  - Neither the web login, the DJ login nor the API accepts an md5 value any more.
  - See *Upgrading* before you install.

### Changed

- **Time fields use the browser's own time input**: Show Builder, Calendar (show content), New /
  Edit Show including rebroadcast times, Playout History, Listener Stats and Show Listener Stats.
  - This replaces the jQuery UI timepicker 0.2.9, unmaintained since about 2014.
  - You can type, use the mouse wheel or the browser's picker. The value stays `HH:MM` (24 h).
  - The display follows the language of the operating system or browser. An English system may
    show 12 h with AM/PM, but the value is still stored as 24 h.
  - Font, height and width match the former fields.
- **Listener Stats chart** runs on Flot 4.2.6 instead of 0.8.3.
  - The mount legend is built as escaped text and keeps its colours when you hide a mount.
  - Resizing is handled by a `ResizeObserver` instead of a polling plugin.
  - It looks the same as before.
- **BlockUI 2.39 (2011) replaced** by a small built-in helper with the same `.block()` /
  `.unblock()` calls and classes. The podcast page no longer throws because BlockUI was missing
  there.
- **`dataTables.columnFilter` removed.** It was loaded on five pages but never ran; the library
  filters with its own code.
- **Release workflow** uses `softprops/action-gh-release` 3.0.4.

### Upgrading from 1.4.0

Follow `docs/operator/UPGRADE.md`. In short:

1. **Before the upgrade, check the password hashes**:
   `python rastatime_api\manage.py password_hashes`.
   - Every account listed as `legacy md5` must log in once on 1.4.0 (that re-hashes it), get a new
     password, or be deleted.
   - After the upgrade such an account can no longer log in until an Admin sets a new password.
   - The same applies to a database restored from a backup taken before 2026-10-27.
2. Make a backup (*Settings → Backup*).
3. Stop the RASTATIME services. The running analyzer locks its executable, so a reinstall with
   the services running fails halfway.
4. Update the checkout and reinstall the five backend packages (`pip install -e`) so the services
   report 1.5.0.
5. No migrations, and no `composer dump-autoload` needed.
6. Start the services in order (`docs/operator/RESTART_ORDER.md`).
   - Liquidsoap's script does not change, so PLAYOUT does not restart it.
   - Restart Apache or reload the browser pages so the new scripts load.

### Known limitations

- Windows only.
- `RASTATIME-WORKER` runs from the source tree. It has no wheel among the release files.
- The `$.browser` compatibility shim stays for now: the context menu and two DataTables plugins
  still read it.

The full change history is in `CHANGELOG.md` (German).
