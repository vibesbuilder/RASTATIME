## RASTATIME v1.9.0 (2026-11-23)

A small feature release on top of 1.8.0:

- Every entry in **System Status → Allowed addresses** gets a **comment** and the **date** it was
  added.
- The manual names a known limitation of **dates in M4A files**.
- The operations documentation describes Icecast 2.5.0 only; the notes on the old 2.4.4 rollback
  are gone.

It has **no database migration**, **no new PHP class** and **no change to the services or the
playout script**: Liquidsoap does not restart. See *Upgrading* before you install.

### Added

- **Comment and date per allowed address** (*System Status → Allowed addresses*, administrators).
  - The list held bare addresses. After a few months nobody knew whose address an entry was, and
    a stale entry (for example the old home address of a DJ) switches off the firewall watcher
    and the login brakes for whoever has that address next.
  - The table now has the columns **Comment** and **Added**. Type the comment into the field next
    to **Add**, or click a comment later to change it: Enter or *Save* stores it, Escape or
    *Cancel* drops the change, and an empty comment removes it.
  - *Allow* from the blocked list never overwrites an existing comment; *Remove* deletes the
    comment together with the entry.
  - The comments are stored under a separate settings key. The address list itself,
    `config/allowlist.txt` and everything that reads it (web login, DJ dial-in, firewall watcher,
    `rt-blocks.ps1`) are unchanged.
  - Entries added before this release have no date.
  - New endpoint `systemstatus/allowed-address-comment` (POST, CSRF token, administrators only).
  - Translations DE / FR / ES.

### Changed

- **Manual: known limitation "dates in M4A files"** (*Library*, all four languages). In an M4A
  file, Expiry, Enable Date, Country and Media Type sit in freeform fields that other tag editors
  and players do not always show or keep when they save the file. This only matters for an M4A
  file that is edited outside RASTATIME and imported again; the dates of a track in the library
  live in the database and are never affected.
- **Operations documentation: Icecast 2.5.0 at `C:\Tools\Icecast`.** `COMPONENTS.md`,
  `RESTART_ORDER.md`, `SERVICE_TOPOLOGY.md`, `CRASH_RECOVERY.md` and `MIGRATION.md` still
  described Icecast 2.4.4 as the installed version or as a rollback. They now describe 2.5.0 at
  the standard path of `INSTALL.md`, with `<charset>UTF-8</charset>` on every output mount.

### Upgrading from 1.8.0

Follow `docs/operator/UPGRADE.md`. In short:

1. Make a backup (*Settings → Backup*).
2. Update the checkout. The change is in the web application's PHP and JavaScript: it takes
   effect with the next request; reload an open *System Status* page once.
3. There is **no migration** and no `composer dump-autoload` is needed.
4. **Apache**: restart it at a quiet moment (no DJ dialling in), which loads the new translations
   of the comment column. Until then those labels show in English.
5. The services and Liquidsoap need no restart for this release. To have the services report
   1.9.0, stop RASTATIME-ANALYZER (it locks its executable), reinstall the five backend packages
   (`pip install -e`) and restart the services in order (`docs/operator/RESTART_ORDER.md`). The
   playout script is unchanged, so a PLAYOUT restart does not restart Liquidsoap.
6. Optional: add a comment to each existing allowed address, so that stale entries can be found
   and removed later.

### Known limitations

- Windows only.
- `RASTATIME-WORKER` runs from the source tree. It has no wheel among the release files.
- The tempo / key worker (`backend/features`) runs from the source tree in its own environment.
  It has no wheel either.
- The Show Source mount takes one client at a time: while the DJ of the show on air is
  connected, nobody can connect early.
- The schedule under a DJ (trial switch since 1.8.0) covers file rows. A web stream or line-in
  row that falls under a DJ still starts when the DJ ends.

The full change history is in `CHANGELOG.md` (German).
