## RASTATIME v1.7.1 (2026-11-17)

A patch release on top of 1.7.0 with one fix to the early show-DJ login. It has **no database
migration** and **no new PHP class**.

### Fixed

- **The ON AIR light flickered while an early show DJ waited.**
  - Since 1.7.0 a show DJ may connect up to five minutes before the show and waits off air. The
    header showed *waiting until …* correctly, but the ON AIR light went off during the wait and
    lit for a few seconds at each track change.
  - Cause: the web application's source priority counted the show source as soon as the DJ was
    *connected*. During the wait it replaced the playing item with a *‹show› - Live stream*
    placeholder, which also reached the title in the header, the now-playing widget and
    `live-info` / `live-info-v2`.
  - The show source now counts once the DJ is *on air* (connected and no longer waiting), the
    same rule the Show Source switch already follows. Until the DJ's show starts, the light, the
    header title and the widgets stay with the show on air; from the start they show the live
    stream as before.
  - The audio, the stream title and the Live Text were not affected.

### Upgrading from 1.7.0

Follow `docs/operator/UPGRADE.md`. In short:

1. Update the checkout. The fix is in the web application's PHP and takes effect with the next
   request; Apache, the services and Liquidsoap need no restart for it.
2. To have the services report 1.7.1, stop RASTATIME-ANALYZER (it locks its executable),
   reinstall the five backend packages (`pip install -e`) and restart the services in order
   (`docs/operator/RESTART_ORDER.md`). The playout script is unchanged, so a PLAYOUT restart does
   not restart Liquidsoap.

### Known limitations

- Windows only.
- `RASTATIME-WORKER` runs from the source tree. It has no wheel among the release files.
- The tempo / key worker (`backend/features`) runs from the source tree in its own environment.
  It has no wheel either.
- The Show Source mount takes one client at a time: while the DJ of the show on air is
  connected, nobody can connect early.

The full change history is in `CHANGELOG.md` (German).
