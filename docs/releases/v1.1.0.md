## RASTATIME v1.1.0 (2026-11-04)

A feature release on top of 1.0.0: archiving on cba.media, alerts by
e-mail and Telegram, the figures for the yearly reporting and
autoloading per episode.  Nothing of 1.0.0 is removed; the new features
are off until you switch them on.

### New

- **Archiving on cba.media** (the archive of the Austrian community
  radios).  Producers (one person or a team per show) and the CBA
  accounts the shows are archived under live in *Settings → Archiving*;
  each show carries its archiving defaults (account, visibility,
  podcast, licence, topic, languages, tags, teaser).  A single episode
  gets its own title, teaser, description, image and number of people
  in the calendar's **Archive Online** dialog, which also uploads it by
  hand.  The uploads run in the `RASTATIME-WORKER` service with a
  bandwidth limit; a failed upload is retried only when nothing can
  have reached cba.media.  **Archive automatically** uploads every new
  episode of a show from its recording once a waiting time after its
  end has passed.  **Analytics → Archive Status** lists the running and
  waiting uploads, what the automatic archiving has ahead, open problems
  and the whole history (filter, CSV), with *Cancel* for a waiting
  upload, *Archive again* and *Link post*.
- **Alerts by e-mail (SMTP) and Telegram** for dead air on the
  broadcast bus, services that stop answering and pre-flight warnings,
  with reminders and an all-clear; one switch per channel and a test
  message for each (*Settings → Alerts*).
- **Figures for the yearly reporting.**  Tick **Own production** in a
  show; **Analytics → Programme Minutes** sums the aired minutes of the
  own productions per month (first broadcasts and repeats apart) and
  **Analytics → People Involved** the people per own production and
  episode.  Both pages export CSV.
- **Autoloading per episode.**  *Edit Instance* can give one episode its
  own autoloading playlist, repeat, intro and outro, as long as it is
  not filled yet.

### Changed

- *Edit Instance* shows the show's Archiving section read-only.
- Show form: the number of people involved sits below *Own production*
  and appears while it is ticked.

### Fixed

- Telegram alerts failed when the Windows certificate store lacked the
  root of api.telegram.org; the `certifi` bundle is trusted as well.
- Autoloading per episode: the values of an instance edit landed on the
  old instance row.
- *Edit Instance* lost the episode's archiving data.
- The upload ZIP for cba.media could not be opened by the server (it is
  now written on its own before the upload).

### Security

- No operator data in the code, hardened GitHub workflows (pinned
  actions, Node 24), dependencies updated after GitHub security alerts,
  public pages reveal neither the product nor internals.

### Upgrading from 1.0.0

Follow `docs/operator/UPGRADE.md`.  In short:

1. Make a backup (*Settings → Backup*).
2. Update the checkout and apply the **five database migrations**
   0074-0078 (`manage.py migrate`).
3. Reinstall the five backend packages (`pip install -e`) so the
   services report 1.1.0.
4. Restart `RASTATIME-API`, `RASTATIME-PLAYOUT`, `RASTATIME-WORKER` and
   Apache (Apache loads the new translations).

Archiving needs a cba.media user with a WordPress application password
per account; alerts need an SMTP server or a Telegram bot.

### Known limitations

- Windows only.
- `RASTATIME-WORKER` runs from the source tree; it has no wheel among
  the release files.

The full change history is in `CHANGELOG.md` (German).
