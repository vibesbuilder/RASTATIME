# Languages (i18n)

> **Where you are in the manual.** This chapter covers the
> language-switching feature visible to every user (via the
> user dropdown) plus the technical detail of adding /
> updating translations for the technical reader.
>
> **Out of scope.** Date formatting and number formatting
> are tied to the browser locale, not to RASTATIME's
> language setting. RASTATIME's language affects UI labels
> only.

RASTATIME ships with **English** and **German** built-in.
French and Spanish translations are present but partial
(machine-translated, marked fuzzy). Every label that
operators see in the web UI passes through `gettext` and
can be translated.

The language can be set:

- **System-wide** — Settings → General Preferences →
  Default Language. The login screen + new users default to
  this.
- **Per user** — User dropdown → **Language** → pick. Saved
  with the user account; takes effect on next login.
- **Per request** — Not directly supported; URL parameter
  override is not implemented.

---

## 1. Switching your own language

Top-right user dropdown → **Language** → pick from the list.

```
   ┌──────────────────────┐
   │  ↓  admin            │
   ├──────────────────────┤
   │  My Profile          │
   │  Language ▾          │
   │    ◉  English (en_US)│
   │    ◯  German (de_DE) │
   │    ◯  French (fr_FR) │
   │    ◯  Spanish (es_ES)│
   │  Logout              │
   └──────────────────────┘
```

The choice is saved with your user account in `cc_subjs`. Log
out and back in (or refresh the page) for the change to take
full effect — the language is loaded once per session at
login.

> **Why does the page partially translate?** PHP templates
> render at request time so they update immediately. Client-
> side JavaScript strings are loaded once when the page loads
> and need a full page refresh to update. Pre-2026-05-15 some
> menu labels even kept their previous-locale value across
> fcgid worker recycling; this is the bug ARCHITECTURE §20.3
> covers + the fix in commit 3b4bcb6.

## 2. The four shipped languages

| Locale | Status | Notes |
|---|---|---|
| **en_US** | Source language, 100 % | The reference. All msgid keys are en_US. |
| **de_DE** | Complete, operator-reviewed | The RASTATIME team's primary German locale. |
| **fr_FR** | Partial, machine-translated | Auto-translated from en_US; fuzzy markers on uncertain strings. Community contributions welcome. |
| **es_ES** | Partial, machine-translated | Same as fr_FR. |

Non-English / non-German upstream LibreTime locales were
removed in commit 1724246 to focus translation effort on
the two operator-supported languages.

## 3. How translations work technically

> **For the technical reader.** Operators can skip this
> section.

### gettext on Windows without msgfmt

RASTATIME runs on Windows where the GNU gettext toolchain
(`msgfmt`) is awkward to install. To avoid forcing operators
to install it, RASTATIME ships a **pure-Python .po → .mo
compiler** at `scripts/compile_messages.py`. The compiled .mo
files are also committed to the repository so a fresh clone
works without running the compiler.

To rebuild .mo files after editing a .po:

```powershell
python scripts/compile_messages.py
```

Or use the convenience wrapper:

```powershell
infra/scripts/maintenance/build-locales.ps1
```

### Where the files live

```
   frontend/legacy/locale/
     en_US/LC_MESSAGES/
       rastatime.po      ← English source (msgid + identical msgstr)
       rastatime.mo      ← compiled
     de_DE/LC_MESSAGES/
       rastatime.po      ← German translations
       rastatime.mo      ← compiled
     fr_FR/LC_MESSAGES/
       rastatime.po      ← French (partial)
       rastatime.mo      ← compiled
     es_ES/LC_MESSAGES/
       rastatime.po
       rastatime.mo
   backend/api/locale/
     de/LC_MESSAGES/
       django.po         ← Django API error messages (German)
       django.mo
   frontend/locales/
     en/common.json      ← JSON form for JS i18n
     de/common.json
```

Three formats:

- **`rastatime.po/.mo`** — gettext format, used by PHP via
  the `_()` and `gettext()` functions on the legacy front-
  end.
- **`django.po/.mo`** — gettext format, used by Django for
  REST API error messages.
- **`common.json`** — JSON form, used by JavaScript via
  `$.i18n._()` for client-side rendered strings.

### Adding a new translatable string

PHP (most common):

```php
// Before
$label = 'Save Changes';

// After
$label = _('Save Changes');
```

JavaScript:

```js
// Before
var label = 'Save Changes';

// After
var label = $.i18n._('Save Changes');
```

Then extract the string into the `.po` files:

```powershell
# From the repo root
xgettext --keyword=_ --output=frontend/legacy/locale/en_US/LC_MESSAGES/rastatime.po \
   $(Get-ChildItem frontend/legacy/application -Recurse -Filter *.php)
```

> **Tip.** RASTATIME does not currently run `xgettext` on
> every commit. For now, add new strings to the `.po` files
> by hand or batch-extract before a release.

### The render-time translation pattern (T20.3)

Some labels — notably the top navigation menu — used to be
translated at *config load* time in
`configs/navigation.php`. That meant the fcgid worker held
the previously-rendered string and a language switch did
not propagate until the worker was recycled. RASTATIME
2026-05-15 (commit 3b4bcb6) moved menu translation to
*render* time in `views/scripts/menu.phtml`:

```phtml
<?php // navigation.php — labels are plain English source strings ?>
<?php // menu.phtml — actually translates at render time ?>
<a href="…"><?php echo _($page->getLabel()); ?></a>
```

Implication for translators: when extracting strings from
the navigation menu, the source you see in
`configs/navigation.php` is the **msgid**, not the
display label.

## 4. Adding a new locale

> **For the technical reader.** Operators can skip this
> section.

Adding (e.g.) Italian:

1. **Pick a locale code.** `it_IT` is canonical.
2. **Create the directories:**

```powershell
mkdir frontend/legacy/locale/it_IT/LC_MESSAGES
mkdir backend/api/locale/it/LC_MESSAGES
mkdir frontend/locales/it
```

3. **Copy `en_US/LC_MESSAGES/rastatime.po` as the
   starting point:**

```powershell
copy frontend/legacy/locale/en_US/LC_MESSAGES/rastatime.po `
     frontend/legacy/locale/it_IT/LC_MESSAGES/rastatime.po
```

4. **Translate the msgstr fields** in the new .po file.
   Open in Poedit (Linux/Mac) or PoEditor (web) for a
   friendlier UI. Mark uncertain translations as `#, fuzzy`.

5. **Compile:**

```powershell
python scripts/compile_messages.py
```

6. **Add the locale to `application/models/Locale.php`'s
   `getLocales()`** so it appears in the dropdown:

```php
'it_IT' => 'Italiano',
```

7. **Optional: translate `backend/api/locale/`'s
   `django.po`** for Italian API error messages.

8. **Optional: translate `frontend/locales/it/common.json`**
   for client-side JS strings.

9. **Test:** log in, switch language, walk through every
   page. Look for English strings that didn't translate —
   those are missing `_()` wrappers in the PHP source
   (file a bug).

## 5. Editing existing translations

The simplest path:

```powershell
# Open in any text editor
notepad frontend/legacy/locale/de_DE/LC_MESSAGES/rastatime.po
```

Find the msgid you want to fix, change its msgstr, save.
Recompile:

```powershell
python scripts/compile_messages.py
```

Browser refresh → updated translation visible.

### PO file format primer

```
msgid "Save Changes"
msgstr "Änderungen speichern"

msgid "Cancel"
msgstr "Abbrechen"

#, fuzzy
msgid "Sometimes uncertain string"
msgstr "Manchmal unsicherer String"
```

- `msgid` — the English source string (immutable).
- `msgstr` — the translated string. Edit this.
- `#, fuzzy` — comment marking the translation as uncertain.
  Remove the comment line once you have reviewed.

### Plural forms

```
msgid "1 track"
msgid_plural "%d tracks"
msgstr[0] "1 Track"
msgstr[1] "%d Tracks"
```

German has the same singular/plural distinction as English.
Other languages may have more (e.g. Russian has 3 forms).
See gettext docs for the per-language `nplurals` count.

## 6. Date and number formatting

These are **not** controlled by the RASTATIME language
setting. They follow the **browser locale** (`navigator.language`
in JS) for client-side rendering, and the **operator
timezone** (Settings → General Preferences → Time Zone) for
server-side rendering.

To get German date format ("21.05.2026" instead of
"05/21/2026"):

- Set your browser language to de-DE (in your OS settings).
- RASTATIME's UI strings can stay in English; only dates
  change.

Server-side date formatting uses the PHP locale set in the
`Locale.php` model, which mirrors the language code.

> **Why split this way?** A user who works in English text
> but prefers ISO date format ("2026-05-21") should not have
> to switch the whole UI to German just for the date. The
> two are decoupled deliberately.

## 7. Frequently-asked

### "I changed the language but some strings are still English."

Causes:

- The string in the PHP source is not wrapped in `_()`. File
  a bug.
- The `.po` file has the msgstr empty for that msgid (it
  falls back to msgid). Edit the .po, add the translation,
  recompile.
- Your browser cached the JS strings. Hard-refresh
  (Ctrl+Shift+R).

### "The 'admin' login page is in the wrong language."

The login page uses the **system default language**
(General Preferences → Default Language) because no user
session exists yet. Set the system default to your
preferred language.

### "Can I have shows in one language and the UI in another?"

Yes. Show names, descriptions, host names are arbitrary
user input — they appear exactly as typed, regardless of UI
language. Only RASTATIME's own UI labels translate.

### "Why is the Django API responding in English when my UI is German?"

The Django API has its own translation set
(`backend/api/locale/`) which may be incomplete for the
language. Currently only German API errors are translated;
others fall back to English.

### "How do I contribute a translation back upstream?"

Open a pull request against the RASTATIME repository with
the updated `.po` files. The compiled `.mo` files are
committed too — run `scripts/compile_messages.py` before
committing. See [`CONTRIBUTING.md`](../../CONTRIBUTING.md)
for the full PR workflow.

### "Can I machine-translate as a starting point?"

Yes — that is how French and Spanish currently work. Run
the .po through DeepL, Google Translate, or a local
translation model, mark every machine-translated string as
`#, fuzzy`, and clean up by hand. The fuzzy marker tells
gettext to use the msgid (English) until the human review
removes the marker.

### "What about RTL languages (Arabic, Hebrew)?"

The UI was designed left-to-right. Adding a RTL language
would require CSS rework on top of the translation. Not
currently in scope; not blocked architecturally, just
unimplemented.
